# RustMusic

Лёгкий клиент YouTube Music с собственным интерфейсом на Rust. Нативное
приложение использует Iced и системный аудиовыход через mpv. Docker-вариант
открывается в браузере и воспроизводит звук на компьютере пользователя.

**Статус: предварительная версия.** Это неофициальный клиент. Доступ к сервису
может потребовать обновления при изменении YouTube Music. Проверки конкретного
Google-аккаунта, библиотеки и изменений плейлистов выполнены на явно
подключённой пользователем сессии. Заявление
об экономии RAM на 50% не делается без сравнительных замеров.

## macOS

Скачайте `.dmg` из [Releases](https://github.com/zalupa-ronaldo/rustmusic/releases),
откройте его и перетащите `RustMusic.app` в Applications. mpv, yt-dlp, Deno и
необходимые библиотеки включены; Homebrew и Python для запуска не нужны.

Первая сборка предназначена для Apple Silicon и **macOS 26.0+**. Нижняя
граница определяется включёнными библиотеками и записана в `Info.plist`.
Сборки подписаны ad-hoc, без Apple notarization. Если Gatekeeper блокирует
первый запуск, разрешите открытие в **Настройки системы → Конфиденциальность
и безопасность → Всё равно открыть**. Не отключайте Gatekeeper целиком.

### Вход в Google

1. Откройте **Аккаунт / настройки → Открыть YouTube Music**.
2. Войдите в Google в обычном браузере.
3. Выберите браузер и профиль (`Default`, `Profile 1` или путь профиля Firefox).
4. Укажите индекс аккаунта из браузерного запроса `X-Goog-AuthUser`, обычно `0`.
5. Нажмите **Подключить выбранный профиль**. macOS может запросить доступ к
   Keychain браузера. Приложение проверяет имя аккаунта перед сохранением.

Альтернатива: импортируйте Netscape `cookies.txt`, JSON с полем `cookie` и
`x-goog-authuser` или строку Cookie из авторизованного запроса `/browse`
в DevTools сайта music.youtube.com. При ручном импорте номер аккаунта задаётся
в поле приложения и имеет приоритет над JSON. JSON-формат:

```json
{"cookie":"__Secure-3PAPISID=...; SID=...","x-goog-authuser":"0"}
```

Сессия — секрет доступа к аккаунту. Приложение сохраняет только cookies,
нужные интеграции. Пароль Google не запрашивается.

На macOS сессия лежит в связке ключей входа, а не в файле. Её записывает и
читает системная программа `/usr/bin/security` (подпись Apple, раздел
`apple-tool:`), с ACL «любое приложение». Поэтому запись остаётся доступной
после пересборки ad-hoc и после переноса Gatekeeper в случайный каталог
AppTranslocation: подпись самого RustMusic при этом меняется, подпись
`security` — нет. Запрос «разрешить доступ» после каждой сборки появляться не
должен. Старый `session.json` из `~/Library/Application Support/rustmusic`
один раз переносится в Keychain и удаляется.

Цена этого решения: любой процесс того же пользователя macOS может прочитать
секрет, запустив `security find-generic-password` для службы
`beer.rustmusic.app`. На диске секрет не лежит открытым текстом и недоступен,
пока связка ключей заблокирована. Более узкий доступ — только приложения с
Team ID Apple — даёт подпись Apple Development или Developer ID; самоподписанный
сертификат на macOS 26 не помогает, система всё равно привязывает запись к
cdhash конкретной сборки. Linux использует Secret Service, Windows — Credential
Manager. Выход удаляет запись из связки; саму браузерную сессию отзывает Google.

## Docker

Требуется Docker Compose v2. Это однопользовательский локальный сервер.

```sh
./scripts/setup-docker.sh
docker compose up --build -d
```

Откройте [localhost:8080](http://localhost:8080). Введите ключ из
`.secrets/server-key` (просмотрите его локально). Затем в настройках импортируйте
сессию Google вручную: контейнер не имеет доступа к браузерам компьютера.

Порт публикуется только на `127.0.0.1`. Для публичного сервера потребуется
отдельная настройка HTTPS, управления доступом и модели пользователей;
эта версия для этого не предназначена.

Сессия шифруется AES-256-GCM в именованном volume. Ключ монтируется через
Docker secret. `.secrets` имеет права `0700`; файл ключа доступен контейнерному
пользователю через отдельный read-only mount. Не удаляйте ключ при сохранённом
volume: старую сессию нельзя будет расшифровать. Удалить Google-сессию можно
в настройках. `docker compose down` останавливает сервис и сохраняет данные.

## Возможности

- Поиск композиций, альбомов, исполнителей и плейлистов.
- Главная страница, библиотека плейлистов и любимые треки.
- Альбомы, страницы исполнителей, рекомендации и радио трека.
- Очередь, предыдущий/следующий, перемотка, громкость, shuffle и repeat.
- Лайки, создание приватного плейлиста, переименование и удаление, добавление,
  удаление и перемещение треков в собственных плейлистах.
- macOS Now Playing и медиаклавиши; Media Session в поддерживаемых браузерах.
- Постраничная загрузка, ограниченные кэши и отмена устаревших запросов.

Нажмите **•••** рядом с треком для действий. Для добавления в другой плейлист
используется его ID из URL YouTube Music; в открытом нативном плейлисте ID
подставляется автоматически. Изменения могут быть отклонены, если вы не
владелец плейлиста. Видео, офлайн-загрузка, тексты песен и несколько
одновременных аккаунтов не входят в эту версию.

## Разработка

Rust 1.95, Node.js 22; для воспроизведения из исходников нужны mpv, yt-dlp
с EJS-зависимостями и Deno. Вспомогательные программы запускаются отдельными
процессами; UI, сеть, модели, управление очередью и сервер реализованы на Rust.

```sh
cargo run -p rustmusic
npm ci --prefix web
npm run build --prefix web
./scripts/setup-docker.sh
cargo run -p rustmusic-server
```

Переменные: `RUSTMUSIC_MPV`, `RUSTMUSIC_YT_DLP`, `RUSTMUSIC_DENO` задают пути
вспомогательных программ. Сервер: `RUSTMUSIC_LISTEN`, `RUSTMUSIC_WEB_DIR`,
`RUSTMUSIC_DATA_DIR`, `RUSTMUSIC_SECRET_FILE`.

```sh
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
npm run build --prefix web
cargo run -p rustmusic-core --example probe
cargo run -p rustmusic-core --example probe_stream
cargo test -p rustmusic real_stream_play_pause_seek -- --ignored
```

Последняя проверка воспроизводит настоящий публичный трек, требует сети и
аудиоустройства. CI не использует личные сессии. Windows/Linux проверяются
на компиляцию и тесты; готовая нативная сборка пока только для macOS.

Сборка `.app` и `.dmg` на Apple Silicon:

```sh
brew install mpv deno
python3 scripts/package-macos.py
```

`Cargo.lock` и `package-lock.json` фиксируют зависимости приложения. yt-dlp
закреплён на `2026.08.19`; его standalone-файл проверяется по upstream SHA256.
Docker фиксирует версии базовых инструментов. macOS-упаковка фиксирует
фактически включённые версии Homebrew-компонентов в `dependencies.json`:
исходники, рецепты, лицензии и checksums выпускаются вместе с бинарником.

См. [API](docs/API.md), [проверки](docs/TESTING.md),
[измерение памяти](docs/PERFORMANCE.md) и [лицензии компонентов](docs/THIRD_PARTY.md).
